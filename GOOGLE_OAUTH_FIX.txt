================================================================================
        FIX GOOGLE OAUTH ERROR 401: INVALID_CLIENT
================================================================================

PROBLEM:
Your Google Client ID doesn't exist or was deleted from Google Cloud Console.

ERROR MESSAGE:
"Error 401: invalid_client - The OAuth client was not found"

SOLUTION:
Create a new OAuth 2.0 Client ID or use an existing one.

================================================================================
                    STEP-BY-STEP FIX
================================================================================

STEP 1: GO TO GOOGLE CLOUD CONSOLE
===================================

1. Visit: https://console.cloud.google.com/

2. Select or create a project:
   - If you see a project dropdown, click it
   - Select existing project OR
   - Click "New Project"
   - Name: "Student Registration System"
   - Click "Create"

STEP 2: ENABLE GOOGLE+ API
===========================

1. Go to APIs & Services:
   https://console.cloud.google.com/apis/dashboard

2. Click "+ ENABLE APIS AND SERVICES" (top)

3. Search for: "Google+ API"

4. Click on "Google+ API"

5. Click "ENABLE"

6. Wait for it to enable (10-30 seconds)

STEP 3: CONFIGURE OAUTH CONSENT SCREEN
=======================================

1. Go to: https://console.cloud.google.com/apis/credentials/consent

2. Select User Type:
   ○ Internal (if Google Workspace)
   ● External (if personal Gmail) ← Choose this
   
3. Click "CREATE"

4. Fill OAuth consent screen:

   App name:
   Student Registration System

   User support email:
   your-email@gmail.com

   Developer contact email:
   your-email@gmail.com

   5. Click "SAVE AND CONTINUE"

6. Scopes Page:
   - Click "ADD OR REMOVE SCOPES"
   - Check: .../auth/userinfo.email
   - Check: .../auth/userinfo.profile
   - Click "UPDATE"
   - Click "SAVE AND CONTINUE"

7. Test users Page:
   - Click "+ ADD USERS"
   - Add your email: your-email@gmail.com
   - Click "ADD"
   - Click "SAVE AND CONTINUE"

8. Summary Page:
   - Review everything
   - Click "BACK TO DASHBOARD"

STEP 4: CREATE OAUTH CLIENT ID
================================

1. Go to Credentials:
   https://console.cloud.google.com/apis/credentials

2. Click "+ CREATE CREDENTIALS" (top)

3. Select "OAuth client ID"

4. Application type:
   Select: "Web application"

5. Name:
   Student Registration Web Client

6. Authorized JavaScript origins:
   Click "+ ADD URI" and add each:
   
   http://localhost:3000
   http://localhost:5001
   
   (Add production URLs later after deployment)

7. Authorized redirect URIs:
   Click "+ ADD URI" and add:
   
   http://localhost:5001/auth/google/callback

8. Click "CREATE"

9. YOU'LL SEE A POPUP WITH:
   
   Your Client ID:
   [Copy this - starts with numbers]
   
   Your Client Secret:
   [Copy this - starts with GOCSPX-]

10. Click "OK"

STEP 5: UPDATE YOUR BACKEND .ENV
=================================

1. Open: backend/.env

2. Update these lines with your NEW credentials:

GOOGLE_CLIENT_ID=YOUR_NEW_CLIENT_ID_HERE
GOOGLE_CLIENT_SECRET=YOUR_NEW_CLIENT_SECRET_HERE
GOOGLE_CALLBACK_URL=http://localhost:5001/auth/google/callback

3. Save the file

4. IMPORTANT: Do NOT commit .env to Git!

STEP 6: RESTART YOUR BACKEND
=============================

If running locally:
```bash
cd backend
npm start
```

If on Render:
1. Go to Render Dashboard
2. Click your backend service
3. Click "Environment" tab
4. Update:
   - GOOGLE_CLIENT_ID with new value
   - GOOGLE_CLIENT_SECRET with new value
5. Click "Save Changes"
6. Wait for auto-redeploy (3-5 minutes)

STEP 7: TEST
============

1. Visit: http://localhost:3000 (or your Vercel URL)

2. Click "Sign in with Google"

3. You should see:
   ✓ Google login page
   ✓ Select your account
   ✓ Consent screen appears (first time only)
   ✓ Redirected back to your app
   ✓ Successfully logged in!

✅ If it works: Success! OAuth is fixed!
❌ If error: Check steps below

================================================================================
                    TROUBLESHOOTING
================================================================================

ERROR: "Access blocked: This app's request is invalid"
SOLUTION:
- OAuth consent screen not configured
- Go back to Step 3
- Make sure to add your email as test user

ERROR: "redirect_uri_mismatch"
SOLUTION:
- Callback URL doesn't match
- Check authorized redirect URIs in Step 4
- Must exactly match: http://localhost:5001/auth/google/callback
- No extra spaces or slashes

ERROR: "Access blocked: Authorization Error"
SOLUTION:
- Your email not added as test user
- Go to OAuth consent screen
- Add your email under "Test users"

ERROR: Still "Error 401: invalid_client"
SOLUTION:
- Client ID/Secret not updated correctly
- Double-check you copied the full values
- Make sure no extra spaces
- Restart backend server
- Clear browser cache

ERROR: "This app isn't verified"
SOLUTION:
- This is NORMAL for development
- Click "Advanced" → "Go to [app name] (unsafe)"
- This happens because app is in testing mode
- For production, submit app for verification

================================================================================
                    PRODUCTION URLS
================================================================================

Once you deploy to production, ADD these URLs:

1. Go back to Google Cloud Console Credentials

2. Click on your OAuth Client ID

3. Authorized JavaScript origins - ADD:
   https://your-backend.onrender.com
   https://your-frontend.vercel.app

4. Authorized redirect URIs - ADD:
   https://your-backend.onrender.com/auth/google/callback

5. Click "SAVE"

6. Wait 5 minutes for changes

7. Update Render environment variables:
   GOOGLE_CALLBACK_URL=https://your-backend.onrender.com/auth/google/callback

================================================================================
                    IMPORTANT NOTES
================================================================================

1. NEVER commit credentials to Git
   - .env is in .gitignore
   - Keep credentials secure

2. Different credentials for different environments:
   - Development: localhost URLs
   - Production: your deployed URLs

3. OAuth consent screen:
   - Testing mode: Only test users can login
   - Published: Anyone can login
   - Verification needed for public apps

4. Client Secret security:
   - Never expose in frontend code
   - Only use in backend
   - Regenerate if compromised

5. Callback URL must match exactly:
   - Protocol (http/https)
   - Domain
   - Port
   - Path

================================================================================
                    COMMON MISTAKES TO AVOID
================================================================================

❌ Wrong callback URL format
✅ Use: http://localhost:5001/auth/google/callback
❌ Not: http://localhost:5001/auth/google/callback/

❌ Forgot to add test user
✅ Add your email in OAuth consent screen

❌ Using old/deleted Client ID
✅ Create new one if old one doesn't exist

❌ Not restarting backend after .env change
✅ Always restart to load new environment variables

❌ Spaces in credentials
✅ Copy exact values, no extra spaces
